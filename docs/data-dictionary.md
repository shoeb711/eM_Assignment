# Data dictionary & synthetic data

All data is **fictional**. Generated by `server/seed/generate.js` from the fixed story in `server/seed/scenario.js`
with a fixed random seed (`20260930`), so every run produces identical CSVs (`data/csv/*.csv`).
`npm run db:import` loads the CSVs into PostgreSQL in one transaction.

## Reporting date
All KPIs use a fixed snapshot of **30 Sep 2026** (`REPORTING_DATE` in `server/.env`). In production this would be
today's date (`CURRENT_DATE`) or a date the user picks - the code reads it from one config value, so the change is one line.

## Derived values (calculated, never stored)
| Value | Definition |
|---|---|
| Project progress % | Σ(task weight × task progress) ÷ Σ(task weight) |
| Overdue task | `status <> 'DONE'` and `due_date < reporting date` |
| High-exposure risk | `score >= 15` and `status <> 'CLOSED'` |
| Current approved budget | initial budget + Σ APPROVED revisions |
| Actual spend | Σ POSTED costs with `txn_date <= reporting date` |
| Remaining budget | current approved budget − actual spend |
| Utilization % | actual spend ÷ current approved budget (shown as "n/a" when the budget is 0) |
| Forecast to complete | Σ forecasts for months after the reporting month (0 for completed/cancelled projects) |
| EAC | actual spend + forecast to complete |
| Projected variance | current approved budget − EAC (negative = forecast overrun) |

Source-of-truth records are the transactional tables above; every KPI is derived from them at query time.
`progress_snapshots` is the only stored history, used for trend context.

## Edge cases built into the data (Section 6)

| Required case | Where |
|---|---|
| Project with no posted spend | PRJ-004 (two draft costs only) |
| Project nearing its budget | PRJ-003 (93% used) |
| Project forecast to exceed its approved budget | PRJ-002 (EAC 3.0M vs 2.65M), PRJ-010 |
| Completed project | PRJ-005 |
| ≥ 5 overdue incomplete tasks | 15 |
| Task due exactly on the reporting date | 1 (PRJ-001) - *due today, not overdue* |
| Unassigned task | 1 (PRJ-006) - alerts go to the project manager |
| Closed high-exposure risk (must not count as open) | PRJ-009, score 20 |
| Open high-exposure risk | PRJ-002, score 20 (+7 others) |
| Returned / rejected change requests | 2 returned, 3 rejected |
| Approved and unapproved budget revisions | approved: PRJ-002, PRJ-009 (linked to approved CRs); pending: PRJ-001, PRJ-010; rejected: PRJ-006 |
| Posted and draft costs | 117 posted, 8 draft |
| Costs after the reporting cutoff | 3 posted in October 2026 (excluded from the 30 Sep snapshot) |
| Project without forecast data | PRJ-008 - **treatment:** forecast-to-complete is taken as 0, so EAC = actual spend, and the project is flagged `FORECAST_MISSING` on the finance page and counted on the dashboard, rather than silently looking "on budget" |
| Several departments and periods | 3 departments; costs from Sep 2025 to Oct 2026 |
